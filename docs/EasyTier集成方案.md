# EasyTier 集成方案（可行性调研 + 详细设计）

> 调研版本：EasyTier v2.6.4（2026-09 实测）· 面板：游戏方舟 GamePanel
> 结论先行：**可行性高，建议分三期落地**。EasyTier 的能力面（多协议 listener、无 TUN 用户态、RPC 管理接口、WireGuard Portal）与面板现有架构（容器管理/多节点/操作异步化）几乎逐一对应。

---

## 一、调研结论与实证

| 调研项 | 结果 | 证据 |
|---|---|---|
| 组网模型 | 去中心化 mesh，`network-name + network-secret` 唯一标识网络；任一可达节点即可加入 | 官方 README + 本机实测 |
| 传输协议 | TCP(11010)/UDP(11010)/WS(11011)/WSS(11012)/WG(11013) listener；KCP 代理抗丢包 | `easytier-core --help` |
| 无 TUN 模式 | **支持** `--no-tun`（用户态）+ `--port-forward`（端口转发） | `--help` 实测确认 |
| 管理接口 | **RPC portal**（`-r` 指定，默认尝试 15888），`easytier-cli peer/route/connector/stun/vpn-portal` 查询 | 本机 `-r 127.0.0.1:15888` 实测返回 route 表 |
| 玩家免装客户端 | **WireGuard Portal**：`--vpn-portal wg://0.0.0.0:11013`，玩家用任意 WG 客户端连接 | 官方 README |
| 魔法 DNS | `hostname.et.net` 直接访问节点 | `--help` |
| 子网代理 | `-n 10.1.1.0/24` 整网段互通（路由自动同步） | `--help` |
| 挂接现有网络 | `-p <peer>` 纯客户端模式**零冲突**（不监听端口） | 本机实测：与系统已运行的 EasyTier 共存成功 |

**本机环境发现**：调研环境已运行系统级 EasyTier（自定义网络，peer 指向自建 VPS 中继，路由表含路由器节点与代理段）。因此面板集成**必须支持"挂接已有网络"模式**，不能只做自建网络。

## 二、集成架构

### 2.1 三种部署形态（按服务器环境自动推荐，用户可改）

```
形态 A：面板托管模式（默认）
  面板以特权容器运行 easytier/easytier 镜像（= 一个"系统实例"）
  ├── --network-host 模式 + /dev/net/tun + NET_ADMIN
  ├── 面板复用现有容器生命周期/日志/监控能力管理它
  └── RPC portal 映射到宿主 127.0.0.1:15888 供面板查询

形态 B：挂接模式（检测到宿主已有 EasyTier 时推荐）
  面板仅用 -p 挂到已有网络的 peer 地址（零监听、零冲突）
  └── 实测验证：与系统已有 EasyTier 共存无误

形态 C：用户态模式（PaaS/VPS 无 TUN 权限）
  easytier 二进制 --no-tun + --port-forward
  └── 游戏端口经用户态转发到虚拟网（性能略降，兼容性优先）
```

### 2.2 游戏实例接入虚拟网（两档）

| 档位 | 方式 | 玩家侧 |
|---|---|---|
| **直连档（推荐）** | 游戏容器加入 EasyTier 容器的 docker network（`--network container:et` 或共享 bridge）→ 获得虚拟 IP，游戏直接监听虚拟 IP | 装 EasyTier 客户端（Win 图形版），填面板生成的"一键加入配置" |
| **免装档** | EasyTier 开 WireGuard Portal（11013） | 玩家用现成 WireGuard 客户端扫面板生成的配置二维码 |

### 2.3 面板改造点（全部映射到现有能力）

| 改造 | 复用的现有模块 | 规模 |
|---|---|---|
| EasyTier 生命周期（启停/日志/状态） | 容器管理 + Ops 异步操作 + WS 实时控制台 | 小：模板加一个"系统服务"实例类型 |
| 组网状态页（节点表/延迟/丢包/NAT 类型） | 新增 `easytier-cli -p 127.0.0.1:15888 peer/route` 的 curl 封装（Process.runOutput，与 Modrinth 同模式） | 小 |
| 邀请配置生成 | 模板渲染（网络名/密钥/peer 地址清单）+ 前端复制按钮 | 小 |
| 游戏实例绑虚拟网 | `Docker.runInstance` 追加 `--network`（现有 node 特例同模式扩展） | 小 |
| 玩家侧端口显示 | 实例详情加"虚拟网地址"字段 | 小 |

## 三、全网络环境矩阵（核心章节）

| # | 服务器环境 | 玩家环境 | 方案 | 关键参数 |
|---|---|---|---|---|
| 1 | 公网 IP（云主机） | 任意 | **形态 A**：全协议 listener（tcp+udp 11010），面板生成公网 peer 地址给玩家；P2P 直连打洞成功率高 | `-l tcp://0.0.0.0:11010 -l udp://0.0.0.0:11010` |
| 2 | 家宽 NAT（无公网 IPv4） | 公网/NAT | **形态 A + 公共/自建中继**：连一个公网 peer（用户的阿里云 VPS 即现成中继；或官方公共节点），UDP 打洞；打洞失败自动中继 | `-p tcp://<VPS>:11010`；`--latency-first` 关闭则优先 P2P |
| 3 | 双端深 NAT（打洞必败，如对称型） | 对称 NAT | **WS/WSS 中继**：中继节点开 ws(11011)/wss(11012)，443 端口可伪装 HTTPS 穿企业防火墙 | `-l ws://0.0.0.0:11011`；wss 需证书 |
| 4 | **PaaS/容器平台（无 TUN）** | 任意 | **形态 C**：`--no-tun --port-forward <虚拟IP:游戏端口>=0.0.0.0:游戏端口`，纯用户态 | `--no-tun --port-forward 10.126.126.1:25565=0.0.0.0:25565` |
| 5 | 纯内网/离线（机房无外网） | 同内网 | **局域网直连**：UDP 广播发现（默认 listener 含 udp://0.0.0.0:11010 即支持局域网 peer 发现） | 同网段自动组网 |
| 6 | IPv6-only 服务器 | IPv4 玩家 | 公网中继做 v4/v6 桥（EasyTier listener 绑 v6 地址） | `-l tcp://[::]:11010` |
| 7 | 玩家 unwilling 装任何 VPN 客户端 | — | **WireGuard Portal**：WG 是各大平台最普及的 VPN 客户端（手机内置支持） | `--vpn-portal wg://0.0.0.0:11013 --vpn-portal-client <wg 配置>` |
| 8 | 面板宿主已有 EasyTier（调研环境实测此情形） | — | **形态 B 挂接**：面板网络实例用 `-p` 连已有 peer，游戏容器接同一虚拟网 | `-p tcp://127.0.0.1:11010` |

**中继节点选型**（环境 2/3 的公共依赖）：
- 官方公共节点（免费，地址见 easytier.cn 公共服务器页，实测 `public.easytier.cn:11010` 系列）
- 自建：任意 VPS 跑 `easytier-core --network-name <中继名> --network-secret <中继名>`（中继模式：网络名=密钥公开），1C512M 即可带几十人
- **用户已有阿里云 VPS peer 可直接复用**（调研发现）

## 四、分期实施计划

### P0（一天内可完成）：核心可用
1. 模板加"EasyTier 组网"系统实例（形态 A 容器：host 网络 + TUN + dhcp；表单：网络名/密钥自动生成/中继 peer 多选/监听协议勾选）
2. 组网状态页：`easytier-cli peer/route` 封装 → 节点表（IP/主机名/延迟/丢包/NAT 类型/隧道协议）
3. 邀请卡生成：网络名+密钥+本机全部可达地址（公网 IP:11010 / 内网 IP:11010 / 中继地址）+ 玩家客户端下载链接，一键复制
4. 游戏实例详情显示"虚拟网连接地址"（EasyTier 容器网络共享模式）

### P1：体验完善
5. 形态 B 挂接模式（检测系统 easytier 进程/11010 占用时提示）
6. 形态 C 无 TUN 模式（docker run 检测 /dev/net/tun 不可用时自动降级 --no-tun + port-forward）
7. WireGuard Portal 集成（勾选即开 11013，生成 WG 客户端配置/二维码）✅ 已落地
8. 玩家上下线审计（peer 增减 → 面板审计日志 + 可选 Webhook 复用现有告警）✅ 已落地（连接动态时间线 + et-stats.json 持久化 + peerNotify 开关推送 peer_join/peer_leave；独立事件历史不混入管理员审计，避免玩家动态刷屏）

### P2：进阶
9. 多节点联动：每个 docker context 节点各跑一个 EasyTier 实例，同网络名组成跨机房 mesh（多节点面板的直接延伸）
10. 按实例隔离的多网络：每游戏服独立网络名（不同朋友圈互不可见）
11. 流量统计报表（peer 表的 rx/tx 采样入监控历史）✅ 已落地（每 30 秒采样，计数器增量累计，对端重连回退自动续算，组网页面节点流量统计表）

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| TUN 权限（部分 VPS/PaaS 禁） | 形态 C 自动降级；创建时探测并提示 |
| 端口 11010/11011 被占（本机实测发生） | listener 全部可配置；挂接模式无监听 |
| 公共中继不稳定/限速 | 方案文档明确自建中继命令行；支持多 peer 冗余 |
| 密钥泄露 = 网络裸奔 | 密钥仅管理员可见（viewer/operator 打码）；邀请卡生成记审计 |
| 性能：中继模式带宽受限于中继 | P2P 优先（latency-first 可配）；状态页展示直连/中继状态让用户可感 |
| 与系统已有 EasyTier 冲突 | 形态 B 挂接；面板启动时探测并存提示 |

## 六、玩家侧接入体验（最终形态）

玩家拿到面板生成的邀请卡后：
1. 下载 EasyTier 客户端（Win/macOS/Linux/Android 图形版，或用现成 WireGuard）
2. 粘贴"一键加入配置"（图形版支持导入完整参数串：网络名+密钥+peer 地址）
3. 客户端自动获得虚拟 IP → 游戏内直接连 `<虚拟IP>:<游戏端口>`（面板实例卡上直接显示这个地址）
4. 面板"组网状态页"实时看到玩家节点上线（延迟/NAT 类型/直连与否）

——对玩家而言即"复制粘贴 → 进游戏"；对服主而言即"面板点开 → 发链接"。
