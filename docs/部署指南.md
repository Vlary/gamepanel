# 部署指南

## 一、环境要求

- Linux x86_64（Ubuntu 22.04+/Debian 12/Arch 等主流发行版）
- Docker 20+（当前用户可执行 `docker ps`，即在 docker 组）
- 仓颉 SDK 1.1.3（编译期需要；运行期仅依赖 SDK 的 runtime 动态库）
- 磁盘：实例数据 + 备份按游戏规模预留（MC 全量备份约 200MB/份起）

## 二、安装仓颉工具链（一次性）

```bash
# 1. 下载 SDK（官网 https://cangjie-lang.cn/download → 1.1.3 Linux x64）
#    本机归档路径示例：
mkdir -p ~/cangjie-dl
curl -L -o ~/cangjie-dl/sdk.tar.gz '<官网下载链接>'
tar -xzf ~/cangjie-dl/sdk.tar.gz -C ~/cangjie --strip-components=1

# 2. 安装 stdx 扩展库（net.http / encoding.json / log 等）
bash -c "$(curl -fsSL https://raw.gitcode.com/Cangjie/cangjie_stdx/raw/main/downloader.sh)" \
  -- 1.1.3.1 -p linux-x64 -d /tmp/stdx
cp -r /tmp/stdx/cangjie-stdx-linux-x64-1.1.3.1/linux_x86_64_cjnative/static/stdx \
  ~/cangjie/modules/linux_x86_64_cjnative/

# 3. 验证
source ~/cangjie/envsetup.sh
cjc --version    # Cangjie Compiler: 1.1.3
```

## 三、构建面板

```bash
cd gamepanel
source scripts/setup-env.sh
cjpm build          # 产物 target/release/bin/main（约 11MB，单文件）
cjpm test           # 可选：跑 11 个单元测试
```

> 若 SDK 安装在非 `~/cangjie` 路径：`export CANGJIE_HOME=/your/sdk` 后重新构建。
> cjpm.toml 的 `link-option` 与 `bin-dependencies` 中包含 SDK 绝对路径，
> 更换路径时执行：
> ```bash
> sed -i "s|/home/vlary/cangjie|$CANGJIE_HOME|g" cjpm.toml
> ```

## 四、运行

### 直接运行

```bash
GP_ADMIN_PASS='强密码' ./scripts/run.sh
```

### systemd 常驻（推荐生产环境）

`/etc/systemd/system/gamepanel.service`：

```ini
[Unit]
Description=GamePanel - 容器化游戏服务器面板
After=docker.service network-online.target
Wants=docker.service

[Service]
Type=simple
User=你的用户
WorkingDirectory=/opt/gamepanel
Environment=GP_PORT=8080
Environment=GP_ADMIN_PASS=你的强密码
Environment=GP_DATA=/opt/gamepanel/data
ExecStart=/opt/gamepanel/target/release/bin/main
Restart=on-failure
# 运行期动态库路径（按 SDK 实际位置调整）
Environment=LD_LIBRARY_PATH=/home/你的用户/cangjie/runtime/lib/linux_x86_64_cjnative

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now gamepanel
```

## 五、安全清单

1. **修改 GP_ADMIN_PASS**（默认 admin123）
2. 面板端口只在内网/VPN 暴露，或用 nginx/caddy 加 HTTPS 反代
3. 服务器防火墙只放行游戏端口（25565/10999/7777/16261...），面板 8080 不对公网开
4. 定期检查 `data/` 目录磁盘占用，配置保留策略（计划任务 keepCount）
5. Minecraft 实例默认开启容器内 RCON（仅容器内可达，未映射到宿主，无外部暴露）

## 六、数据与迁移

- 全部状态在 `GP_DATA` 目录：`db.json`（元数据）、`instances/`（各实例数据目录）、`backups/`、`snapshots/`
- 迁移到新机器：`rsync -a data/ newhost:/opt/gamepanel/data/` + 拷贝二进制 + 起新面板（容器会自动重建）
- 灾难恢复：任意一份全量备份 tar.gz 可直接 `tar -xzf` 到实例目录完成恢复

## 七、常见问题

**Q: 创建实例后状态一直是 missing？**
镜像在后台拉取。本机执行 `docker pull <镜像>` 查看进度；国内网络可配置 Docker 镜像加速。

**Q: 命令发送失败？**
Minecraft 依赖镜像内置 rcon-cli（面板已默认开启 RCON，仅容器内访问）。其他游戏依赖镜像 stdin 控制台，个别镜像可能不支持，日志查看不受影响。

**Q: 饥荒起不来？**
DST 必须填 `DST_CLUSTER_TOKEN`（创建实例时加入「自定义环境变量」）。

**Q: 恢复备份时报"请先停止实例"？**
设计如此：恢复前先在面板点「停止」，避免写入冲突。
